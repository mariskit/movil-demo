DESARROLLO MÓVIL 02 / 09

El ciclo de vida
no conserva todo.

ESTADO DE INTERFAZ

Rotación, navegación y proceso

  • remember: conserva estado entre recomposiciones.
  • ViewModel: sobrevive a cambios de configuración; no a la muerte del proceso.
  • rememberSaveable / SavedStateHandle: restauran pequeños estados de UI bajo condiciones del sistema.
DATOS DE LA APLICACIÓN

Persistencia duradera

  • Room: notas y tareas.
  • DataStore: configuración.
  • Archivos privados: adjuntos.

Una nota guardada debe recuperarse en una nueva ejecución, sin depender de la pantalla anterior.

En Android, no dependas de onDestroy() para guardar: el sistema puede terminar el proceso sin llamarlo.

Escritura

  1. El usuario pulsa Guardar.
  2. Se valida y se solicita la inserción.
  3. Se espera el resultado; se informa un fallo si ocurre.

Lectura reactiva

  1. El DAO expone Flow<List<Note>>.
  2. El ViewModel expone el estado de UI.
  3. Compose observa con collectAsStateWithLifecycle().

Room ofrece consultas asíncronas con suspend y Flow. Para archivos con APIs bloqueantes, usa un contexto adecuado como Dispatchers.IO.

y acceso a datos.

KOTLIN · ENTIDAD Y DAO · ESQUEMA V1

@Entity(tableName = "notes")
data class Note(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val text: String
)

@Dao
interface NoteDao {
    @Insert
    suspend fun insert(note: Note)

    @Query("SELECT * FROM notes ORDER BY id DESC")
    fun observeAll(): Flow<List<Note>>

    @Query("DELETE FROM notes WHERE id = :id")
    suspend fun delete(id: Long): Int
}

Contratos explícitos

Entity: define columnas y clave primaria.

DAO: concentra inserciones, consultas y borrados.

Parámetros enlazados: :id evita construir SQL concatenando valores.

Validación: Room comprueba las consultas contra el esquema al compilar.

Fragmento: requiere dependencias, imports, RoomDatabase e inicialización. No es una app completa.

KOTLIN · REPOSITORIO Y FRAGMENTO DE VIEWMODEL

class NoteRepository(private val dao: NoteDao) {
    val notes = dao.observeAll()
    suspend fun add(text: String) {
        dao.insert(Note(text = text.trim()))
    }
}

// Dentro del ViewModel; repository está inyectado.
fun save(text: String) = viewModelScope.launch {
    if (text.isBlank()) return@launch
    try {
        repository.add(text)
        // Emitir estado: guardado confirmado.
    } catch (e: CancellationException) {
        throw e
    } catch (e: Exception) {
        // Emitir estado de error para la interfaz.
    }
}

Sin bloquear la pantalla

viewModelScope vincula la corrutina al ViewModel.

Espera la inserción antes de confirmar el guardado.

Deshabilita el botón mientras se guarda para evitar envíos repetidos.

Propaga la cancelación y comunica los errores.

Una corrutina del ViewModel no garantiza trabajo después de morir el proceso. Para tareas diferibles y persistentes, evalúa WorkManager.

DESARROLLO MÓVIL 07 / 09

Actualizar la app
sin perder las notas.

MIGRACIÓN · V1 → V2

Agregar una nota fijada

val MIGRATION_1_2 = object : Migration(1, 2) {
    override fun migrate(db: SupportSQLiteDatabase) {
        db.execSQL("""
            ALTER TABLE notes ADD COLUMN
            pinned INTEGER NOT NULL DEFAULT 0
        """.trimIndent())
    }
}

V2: agregar @ColumnInfo(defaultValue = "0") val pinned: Boolean = false a la entidad, aumentar la versión y registrar la migración.

INTEGRIDAD Y VERIFICACIÓN

Datos coherentes

  • Usar @Transaction o withTransaction para operaciones relacionadas.
  • Probar la migración con registros de la versión anterior.
  • Comprobar conservar texto, IDs y valor inicial de pinned.
  • Evitar migraciones destructivas para datos que deban conservarse.

DESARROLLO MÓVIL 08 / 09

Seguridad en
el dispositivo.

ALMACENAMIENTO PRIVADO

Aislamiento y cifrado

  • El sandbox limita el acceso de otras apps; no equivale a cifrado.
  • Room no cifra automáticamente la base de datos.
  • Keystore protege claves; el cifrado del contenido requiere una solución adicional.
CICLO DE VIDA DE LOS DATOS

Respaldo y eliminación

  • Definir qué información entra en las copias de seguridad.
  • Separar datos por cuenta y limpiar según la política de cierre de sesión.
  • No escribir tokens, contraseñas ni datos sensibles en logs.

Borrar datos o desinstalar suele eliminar el almacenamiento privado; una copia de seguridad puede restaurarlo según la configuración.

Al guardar sin conexión

Una transacción persiste la nota y una operación pendiente. La UI observa el cambio local.

WorkManager programa el envío cuando se cumplan las condiciones de red.

Al recuperar conexión

Usa identificadores e idempotencia para tolerar reintentos. Marca como enviado tras la confirmación.

Define resolución de conflictos: versión, combinación de cambios o intervención del usuario.

La persistencia permite recuperar datos. La sincronización mantiene coherencia entre dispositivos: son responsabilidades diferentes.
